# baked-secrets-patterns.txt — the reviewed pattern list for
# harness/scan-baked-secrets.sh (GitHub #154: gate-time negative scan
# enforcing the never-bake-values rule, R2 docs/PRE_SEEDED_HARNESS_RESEARCH.md
# §4 "bake placeholders hsurr:<name>, never values").
#
# This file is reviewed like code: every rule needs a rationale a reviewer
# can weigh (hit = gate refusal, so a false-positive-prone rule blocks
# image publishes). Prefer fixed-shape, low-false-positive patterns;
# heuristic shapes are marked as such.
#
# Line format:  KIND: ID: RULE
#   KIND  content — RULE is an extended regex (grep -E) matched against
#                   file bytes anywhere under the scan target.
#           name    — RULE is a shell glob matched against file basenames
#                   (find -name) anywhere under the scan target.
#           allow   — RULE is an exact string; a secrets-dir value file
#                   holding exactly this content is not a hit (the public
#                   gate-fixture dummy only).
# ID is a short slug naming the rule in hit reports. Blank lines and
# lines starting with '#' are ignored. The regex may itself contain ':'
# (split is on the first two colons only). Trailing whitespace (including
# CR) is stripped from every rule — a CRLF-edited file must not silently
# weaken the patterns, and no rule intentionally ends in whitespace.
# There is deliberately no content-allowlist kind: a legitimate baked
# string matching a heuristic pattern is handled by editing this file
# (reviewed like code), not by a local exception.

# --- content: real secret material must never be baked --------------------
# Any PEM private-key block: directly enforces the manifest's baked[]
# claim "CA generated per tenant at first boot; private key never baked".
content: pem-private-key: -----BEGIN ([A-Za-z0-9 ]+ )?PRIVATE KEY-----
# AWS access key IDs have a fixed, unmistakable shape.
content: aws-access-key-id: AKIA[0-9A-Z]{16}
# GitHub personal access tokens, classic (fixed shape) and fine-grained.
content: github-token: ghp_[0-9A-Za-z]{36}|github_pat_[0-9A-Za-z_]{22,}
# OpenAI-style secret keys. HEURISTIC: the 'sk-' prefix is short; the
# 20+ alnum tail keeps prose false positives near zero.
content: openai-api-key: sk-[0-9A-Za-z]{20,}
# Anthropic API keys. Fixed, unmistakable prefix.
content: anthropic-api-key: sk-ant-[0-9A-Za-z-]{20,}

# --- name: credential-shaped filenames must never be baked ----------------
# This rule is deliberately stricter than the values rule: even a
# placeholder-only .env is refused, because the filename itself advertises
# "secrets live here" to anyone reading the image. The surface is narrow on
# purpose — only names that are secret-shaped by themselves. Deliberately
# NOT included: *.pem / *.key (certificates and public keys are fine to
# bake; the content patterns catch private-key material wherever it hides),
# credentials.json (the registry is metadata, and the value dirs it points
# at are covered by the secrets-dir rule), .aws/credentials (path-qualified;
# the basename alone is too common to fail a gate on).
# SSH private keys by their conventional filenames.
name: ssh-private-key: id_rsa
name: ssh-private-key: id_ed25519
name: ssh-private-key: id_ecdsa
name: ssh-private-key: id_dsa
# Conventional secret-bearing files.
name: dotenv-file: .env
name: dotenv-file: .env.*
name: netrc-file: .netrc
name: netrc-file: _netrc
name: auth-json: auth.json
# PKCS#12 bundles are always credential material (private key + certs).
name: pkcs12-bundle: *.p12
name: pkcs12-bundle: *.pfx

# --- allow: exact public values that are not secrets ----------------------
# The gate fixture's public dummy (harness/install-gate-fixture.sh
# FIXTURE_DUMMY): baked into the repo on purpose, obviously-not-a-key.
# The image-build gate installs it under llm-api before the round trip,
# so a secrets-dir value holding exactly this string is not a leak.
allow: gate-fixture-dummy: GATE-FIXTURE-DUMMY-NOT-A-SECRET
