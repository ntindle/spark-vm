# playwright_browser_hashes.txt — SHA-256 pinned browser-archive downloads
# for the toolset updater's playwright layer (issues #532, #1017).
#
# Format: one `<sha256>  <url>` line per pinned archive. Blank lines and
# `#` comments are ignored. The updater (`deploy/toolset-update.sh`,
# `_playwright_layer`) derives the exact archive URLs the hash-verified
# playwright package would fetch (`playwright install --dry-run chromium`,
# parsed fail-closed) and looks each URL up here; a URL with no
# exactly-one well-formed hash line refuses fail-closed instead of a
# TLS-only fetch.
#
# Hash authority: Playwright publishes no archive hashes upstream, so the
# hashes are recorded here at commit time by the maintainer from the CDN
# download the pinned playwright package names (fetched over TLS). The
# threat this closes is narrow by construction — the archive revision is
# already bound by the hash-verified pip package (its browsers.json), so
# the only unaddressed case was a CDN serving different bytes for the same
# revision URL. The installed copy (see `toolset-update.sh install`, which
# copies this file into the state dir next to self_update_pins.conf) is
# the runtime authority. The update plane never reads this file from the
# live checkout.
#
# Discipline: bump this file in the same PR that bumps the playwright pin
# in scripts/self_update_pins.conf. The test suite pins the sync
# (test_playwright_browser_hashes_cover_pins_conf): the file names the
# playwright pin it was captured for, and every archive the pinned
# playwright's `install chromium` fetches on linux must have exactly one
# well-formed hash line. Only the linux archives are listed — spark-vm
# boxes are linux.
#
